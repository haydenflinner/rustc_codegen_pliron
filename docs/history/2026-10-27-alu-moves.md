# ALU and move bloat on regex-syntax: patterns, two fixes

Follow-up to 2026-10-27-code-size. regex-syntax at `-O
-Ccodegen-units=1 --emit=obj`, aarch64. Classes as there; inline
jump-table words (`udf`) excluded from every count below.

## Where the extra ALU / mov / cmp come from

Mnemonic split of the growth (pliron - LLVM): `mov reg, reg` +4,662,
`add reg, reg` +2,407 (mostly the `umulh`+`add` opaque-zero idiom before
cold calls, owned elsewhere), `cmp reg` +1,788, `uxtb` +1,016 (LLVM 0),
`and #imm` +793, `tst #imm` +520 (LLVM 10).

Patterns, counted crate-wide by scripts over `llvm-objdump` output
(scratchpad `alu/pat.py`, `alu/edge.py`; default build before
f6af4a2):

| # | pattern | pliron | LLVM | saved (measured or est.) |
|---|---|---|---|---|
| 1 | split-edge blocks `mov*; b` (one per critical edge); 887 of 1,591 are byte-identical to another in the same function | 1,591 blocks, 1,854 movs | 199 blocks | **1,456 measured** for the `br_table` subset (fix B); the rest are cross-pred (see #4) |
| 2 | i8/i16 re-normalization: `uxtb`/`uxth`, `tst #0xff` | 1,016 `uxtb`, 372 `tst+b.cc` | 0 / 1 | **940 measured** (fix A) |
| 2a | — return-value `uxtb` after a value already zero-extended (`and #k`, `mov #k`, `cset`) | 309 of 381 | 0 | |
| 2b | — `uxtb` from `ireduce` right before `and #k` (UTF-8 bytes, bitfields) | ~200 | 0 | |
| 2c | — `brif` on a byte from `ldrb`/`uxtb`: `tst #0xff; b.ne` instead of `cbnz` | 254 | 0 | |
| 3 | three-way compare / `Option<Ordering>` tests: `cmp; cset hi; cmp; cset lo; sub` then `sxtb; cmp; cset lt; uxtb; cmp #0xfe; csel; tst; csel`, where LLVM emits `cmp; cset lo` | 124 sites, 77 `cmp #0xfe` | 0 | ~800-1,000 (est., ~8 per site) |
| 4 | cross-pred edge moves: several `cbnz; mov x0, x23; b join` blocks moving the same call result back into the join's `x0` param | 632 dup blocks, 1,336 insns | — | regalloc coalescing; est. ~600 |
| 5 | constants hoisted then spilled (`mov #k; str [sp]`, reloaded later; also `movi v0, #0` spilled to a 16-B slot reached via `mov x16, #off`) | 336 | 46 | stack/spill owner |
| 6 | `umulh x, x, K` + `add` opaque zero before cold calls | 1,416 | 11 | owned elsewhere |

Not significant: `cmp + cset + cbnz` (0 sites; Cranelift already
branches on flags), repeated `movz/movk` constant materialization
(`mov #imm` is +267 only, 7%).

## Fix A: clean narrow ints (`PLIRON_NARROWEXT=1`, default off)

Cranelift keeps i8/i16 values with undefined high bits, so every
consumer that cares re-extends. Patch 36 already had a
`val_already_extended` oracle for compares. Vendored Cranelift patch 62
widens it (`narrow_uext_clean`, budget 16: canonical narrow `iconst`,
`band` with one clean operand, `bor`/`bxor` of two clean operands) and
uses it in four more places: the `uext` return-slot extension in
`Lower::gen_return` (new `LowerBackend::narrow_ret_uext_clean`),
`uextend` passthrough, `brif`/`select` on a clean narrow value (`cbnz w`),
and `band (ireduce x) k`, which now masks `x` directly so the `ireduce`'s
`uxtb` is never materialized.

## Fix B: shared `br_table` edge blocks (`PLIRON_EDGEDEDUP=1`, default off)

Cranelift splits every critical edge per (pred, successor index), so a
`match` whose N arms all forward the same value to the join got N
identical `mov; b` blocks behind the jump table. Patch 63 maps table
entries with the same block call (target and args) to one edge block,
and `lower_branch_blockparam_args` gives regalloc2 that edge once.

## Numbers

Baseline is `PLIRON_COLDCOPY=1` (f6af4a2), which already removes the
`umulh` zeros (pattern 6). Instructions from objdump, `udf` excluded:

| | `__text` B | total | ALU | mov | cmp/csel | branch | `[sp]` ld | `[sp]` st |
|---|---|---|---|---|---|---|---|---|
| LLVM | 184,752 | 46,188 | 7,477 | 7,950 | 4,309 | 7,422 | 3,420 | 2,934 |
| baseline | 386,512 | 95,577 | 16,541 | 14,781 | 7,690 | 13,995 | 15,339 | 8,796 |
| `NARROWEXT=1` | 382,956 | 94,637 | 16,035 | 14,839 | 7,436 | 14,003 | 15,154 | 8,733 |
| `EDGEDEDUP=1` | 380,752 | 94,121 | 16,537 | 14,433 | 7,690 | 13,393 | 14,955 | 8,680 |
| both | 377,100 (-2.4%) | 93,180 (-2,397) | 16,040 | 14,470 | 7,436 | 13,397 | 14,751 | 8,662 |

Pattern counts, baseline → both: `uxtb` 1,002 → 492; return `uxtb`
381 → 68; `tst #0xff; b.cc` 373 → 119; edge blocks 1,819 → 1,534
(identical-duplicate blocks 1,026 → 751, the rest cross-pred). Fewer
edge blocks also cut spill traffic (-588 `[sp]` loads) and `b`s (-598).
The pattern table above was counted on the pre-COLDCOPY default build;
the counts it shares with this baseline are within a few percent.

Without the knobs the object is byte-identical to the baseline.
Compile time: no measurable change (two O(1) map lookups per table
entry; the cleanliness walk is budgeted at 16 nodes).

Tests: `pliron-clif-opt/tests/narrowext_lower.rs` (aarch64 asm checks;
six fail with the knobs off; a two-entry table sharing default and entry guards the regalloc-side edge skip), `tests/narrowext` stanza (pinned stock
checksum; plain, `-O` and debug with both knobs).

## Next

Pattern 3 is the best remaining ALU target and needs an IR fold, not
isel: `icmp slt (select (icmp ult a b), -1, (icmp ne a b)), 0` → `icmp
ult a b`, pushed through the lexicographic block-param join, and the
`== -2` (`None`) test folded away by the {-1, 0, 1} range. Pattern 4
needs regalloc to prefer the join param's register for the call result.
