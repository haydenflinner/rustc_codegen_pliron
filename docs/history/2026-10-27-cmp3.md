# Three-way compares and `Ordering` tests through joins (`PLIRON_CMP3`)

Follow-up to pattern 3 in 2026-10-27-alu-moves. regex-syntax at `-O
-Ccodegen-units=1 --emit=obj`, aarch64, baseline env `PLIRON_REMATCALL=1
PLIRON_NARROWEXT=1 PLIRON_EDGEDEDUP=1`.

## Where the pattern comes from

pliron has no `three_way_compare` override, so `BinOp::Cmp` takes the
`rustc_codegen_ssa` default: at `-O`, `select lt, -1, (select ne, 1, 0)`
(`traits/builder.rs`). Cranelift's `spaceship.isle` and clifpeep's
`selord` mask algebra both collapse a test of that value, `(a <=> b) < 0`
→ `a <u b`, but only when the test reads the `select` tree directly.
A derived lexicographic `cmp`/`partial_cmp` merges one spaceship per field
into a join block param (`match a.cmp(b) { Equal => next, c => c }`), and
the caller's test runs on the param:

```
block2(v42: i8):                 ; v42 = field-0, -1 or field-1 spaceship
    v44 = icmp eq v42, -2        ; Option<Ordering> None niche
    v45 = icmp slt v42, 0        ; is_lt
    v46 = select v44, 0, v45     ; partial_cmp(..).is_some_and(is_lt)
```

`PartialOrd::lt` is `self.partial_cmp(other).is_some_and(Ordering::is_lt)`,
so every derived `<` on a struct has this shape, and `sort`, `median3`,
`binary_search` (`== Less`, `== Equal` on one param) inline it per
comparison. The spaceship survives as `cmp; cset hi; cmp; cset lo; sub`,
the `== -2` as `uxtb; cmp #0xfe; csel`, and the `< 0` as
`sxtb; cmp; cset lt`, where LLVM emits `cmp; cset lo` in each predecessor.

## The fold

New CLIF step `cmp3` (`pliron-clif-opt/src/cmp3.rs`), before
`mergechain`/`jtround`, `Gate::OptIn("PLIRON_CMP3")` (default off;
`PLIRON_CMP3=0` keeps it off).

1. Small value sets. Every integer value in the cone of an `icmp x, K`
   gets the set of values it can take, at most four, else top: constants,
   compare results `{0,1}`, `select` = union (or one arm on a known
   condition), extends/narrows element-wise, `iadd`/`isub`/bit ops by
   cross product, block params = union of incoming args, each arg narrowed
   by its edge's own `brif (icmp arg, K)`. The fixpoint is an optimistic
   worklist on a finite lattice. Entry params, non-value edge args, and
   values past the 16k cone budget are top. A compare that gives the same
   result for every element becomes a constant, and a `select` on a
   constant aliases its arm. This removes the `== -2` test whenever no
   edge can carry None.
2. Push-through. If every use of a block param `p` is `icmp cc p, K`
   (directly or through one `uextend`/`sextend`), each distinct compare
   becomes a new i8 param. Each incoming edge computes it: a constant when
   the arg's edge-narrowed set decides it, otherwise the same compare on
   the arg, which `selord_icmp` (now `pub(crate)`) folds on the spot to
   one `icmp` of the field operands. `p` drops, and the spaceships die.
   Blocks are visited in CFG post-order, so compares pushed into an inner
   join (`Span` of two `Position`s) are pushed again. A small instruction
   score (join compares saved, +3 per `select`/`isub` arg, +1 per bool
   `icmp` arg, minus extra constant moves per edge and the opaque args'
   own compares) must be positive. Without it, syn's enum-discriminant
   joins (eight constant edges and one opaque edge, two compares) grew
   by 2 movs per edge.

Both moves are linear: one scan for the edge map, one for the cone, one
for the use lists; new instructions are added to the use lists by entity
index range.

## Numbers

Same build of the backend, flag off and on (`__text` bytes;
instructions from objdump, `udf` excluded):

| | `__text` | insns | cmp/csel | ALU | `cset hi;cset lo` | `cmp #0xfe` |
|---|---|---|---|---|---|---|
| LLVM | 184,752 | | | | 2 | 0 |
| `CMP3` off | 383,596 | 90,567 | 7,425 | 19,554 | 124 | 77 |
| `CMP3=1` | 378,924 (-1.2%) | 89,389 (-1,178) | 6,807 | 19,255 | 0 | 0 |

The previous agent estimated 800-1,000; the measured result is 1,178.
syn: `__text` 1,425,100 → 1,425,100 and -11 instructions, so neutral.
Before the score gate syn was +288 B.

Repro file (`u_lt`, `p_lt`, `sortp`, `binary_search` on a 3-field derived
struct): total 6,438 → 6,056 instructions. `binary_search`'s join
(`== Equal`, `== Less` on one param) loses all three spaceships, and
`p_lt` matches LLVM's `cmp; cset lo; b.ne` per field.

Bench kernels: only `varint::sum_postcard` changes (+8 instructions,
register allocation after two compare folds), so the fold does not touch
`sortw` (`u64` sort, no `Ordering` join).

`bench/run.sh 'sortw|varint'` (pliron/LLVM median, plain → `CMP3=1`,
both under the heavy lock, load ~15): sortw 0.83 → 0.94, varint
0.95 → 1.01, varint_postcard 0.82 → 0.93. sortw's code is byte-identical
in the two builds, so a swing of this size is noise. Absolute pliron
times: sortw 6.20 → 6.53 ms (same code), varint_postcard 5.50 → 5.99 ms
(+8 instructions). varint_postcard needs a quiet A/B rerun before the
default flips.

## Tests

- `pliron-clif-opt/tests/cmp3.rs`: interpreter before/after on boundary
  i64 inputs, plus a shape check, for five cases: a lexicographic
  `is_some_and(is_lt)` join (None test gone, param gone), two queries
  with a `uextend` on one param (binary_search), a reachable `-2` edge
  (the None test must stay), a non-compare use (no push, but the
  impossible `== 2` folds), and a loop-carried ordering.
- `tests/cmp3` stanza (`test.sh`): every `Ordering` and `Option<Ordering>`
  test form (`==`/`!=` per variant, `is_lt`..`is_ne`, `matches!`,
  `is_some_and`, `map_or`, `reverse`, `then`), the four operators. It
  covers u8..u128, i8..i128, char, bool, usize, f32 and f64 (NaN,
  ±0, ±inf) at the boundaries, two-field and nested derived structs, and
  `sort`, `sort_unstable_by`, `binary_search`, `partition_point`,
  `min`/`max`. Each result is checked against a truth table indexed by a
  reference ordering, and a checksum pinned from stock rustc. It runs
  plain, `CMP3=1 -O`, and `CMP3=1` debug.

`harness/gate.py` passed plain and with `PLIRON_CMP3=1` (78 jobs each,
479ec83). `PLIRON_CMP3=1 harness/run.py --suite fuzz --fuzz-seeds
12700:13000` passed 300/300. With the knob off the step does not run,
so default output is unchanged.

## Next

- Float `partial_cmp` tests stay in-block and are not covered:
  `matches!(a.partial_cmp(&b), Some(Less))` on f64 is
  `select (fcmp le), (icmp eq (fcmp ge), 0), 0` (`fcmp; cset ge; cmp;
  cset eq; fcmp; csel`, 6 instructions, where LLVM uses `fcmp; cset mi`).
  It needs a 4-class (lt/eq/gt/uno) mask version of `selord` for `fcmp`.
- Score-0 pushes (one opaque edge, the rest constant) are rejected. They
  would let `jtround` thread the constant edges, but they made loop
  headers in syn worse. Admitting them for non-header joins is untested.
- The push runs once, before `jtround`. Joins that later passes create
  (taildup, mergechain) are not revisited.
