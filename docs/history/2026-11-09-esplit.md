# esplit: edge-specialising small merge blocks (PLIRON_ESPLIT)

Motivation: `chars_ascii`/`chars_alpha` UTF-8 decode scans emitted ~12
insns/ASCII-char vs LLVM's ~9. The merge block after the decode
(`block91(c, ptr)` shape) re-runs `icmp ult c,128; uextend; iadd` even
though the ASCII predecessor edge exits a `band byte,128 == 0` test
that already proves `c < 128`. egraph's GVN creates these merged tails
late in the pipeline, so esplit runs after `egraph2`, before
`iconst128`.

Mechanism: for each small pure `jump`-terminated merge block, evaluate
the body once per predecessor edge under that edge's facts — the brif
arm's `icmp`/raw truth fact, `band x,M` mask inversions against zero,
and per-arg `Ranges` intervals — via `jumpthread::eval`. An edge
qualifies when it folds an inst the param-join env cannot. The block is
cloned for that edge alone and the folded results materialised as
`iconst`; dead params/instructions are left to `deadp`/dce.

Two soundness guards came out of corpus verifier failures:

- **Escaping defs**: a value bound at the merge block (param or body
  result) used in a dominated block outside it would lose its def on
  the clone's path — the clone reaches the successors carrying only
  edge args. `Uses::escapes` rejects such blocks wholesale.
- **Loop-header entry**: cloning the last non-dominated pred (a
  preheader edge) leaves the header reachable only through its own
  back edges, so its params stop dominating in-loop uses. Entry edges
  are cloned only while another entry remains.

Numbers: chars_ascii 2.473ms -> 1.651ms (-33%; LLVM 1.567ms),
chars_mixed ~-1%, chars_alpha flat (its 2.2x gap is a different
mechanism). Corpus `report --check`: 4870 fns, 0 verifier failures,
+214 insts over the 12 fns it fires on (LineRows +48, Command::new
+35) — a hot-path trade. `PLIRON_ESPLIT_LIMIT=N` caps applied clones
for bisection. Landed opt-in in 4f17d95, flipped to `DEFAULT_ON` after
the corpus and gate were clean.

Not done: the second mechanism in the same kernel — LLVM's
post-indexed `ldrsb [x],#1` vs Cranelift's separate `ldrb`+`add` —
needs aarch64 post-increment addressing-mode formation.
