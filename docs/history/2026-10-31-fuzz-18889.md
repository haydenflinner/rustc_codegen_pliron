# Fuzz seed 18889: a bool half of a pair return came back as i8

**Symptom.** The rustlantis program for seed 18889 printed a different
hash from stock rustc when built with pliron at `-Zmir-opt-level=0`. The `-O` build matched only by luck. No
`PLIRON_*` knob changed the result, and `PLIRON_OPT_FNS=~zzzz` (optimize
nothing) did not either, so the bug was in the front half, not in a pass.
It was on main at fea001b and earlier.

## Narrowing

- `dump_var` is ordinary Rust, so it was changed to `#[track_caller]` and
  to print the running hash and a hash of each argument after every call.
  The 13th call (in `fn17`) was the first to differ, in `val2 = _66`, a
  bool.
- `_66 = !_62.0.1`, and `_62: ((bool, bool),)` is the return value of
  `fn18`. `fn18` returned `(false, false)` correctly (its final CLIF).
- The pre-pipeline CLIF of `fn17` already had
  `v4518 = bxor.i8 v4451, -1` on the call's second result. So `!false`
  became `0xff`, and hashing that bool wrote the byte 0xff, not 1.
- A 20-line program reproduces it at every opt level:
  `fn bb(a: bool) -> (bool, bool)`, then `(!bb(false).1) as u8` gave 255.

## Cause

`CodegenCx::immediate_backend_type` (`src/type_of.rs`) returned the memory
type (`layout_type`) for a `ScalarPair`, which is `{i8, i8}` for
`(bool, bool)`. `fn_decl_backend_type` uses this type for a
`PassMode::Pair` return. rustc_codegen_ssa builds the return with
`immediate_or_packed_pair` and unpacks the call result with
`from_immediate_or_packed_pair`. Neither truncates: they expect the
immediate pair type to hold immediate elements, as cg_llvm's
`immediate_llvm_type` does (`{i1, i1}`). The caller therefore got an i8
"immediate" bool. `Builder::not` emits `xor v, -1` at the value's type.
On i1 this lowers to `bxor 1`; on i8 it gives 0xfe/0xff.

Pair parameters were already right, because they use
`scalar_pair_element_backend_type(.., true)`. Only returns (and the few
intrinsics that build their result type with `immediate_backend_type`)
used the memory type.

## Fix

`immediate_backend_type` maps a `ScalarPair` to
`{imm(a), imm(b)}`, the same as cg_llvm. A bool half is i1. The CLIF
signature does not change (i1 lowers to i8), so only the IR types and the
truncation seen by cg_ssa change.

## Evidence

- Seed 18889 prints the stock hash at `-Zmir-opt-level=0` and at `-O`.
- `tests/pairret/main.rs` (the new `pairret` stanza, run at
  `-Zmir-opt-level=0` and `-O`) covers `(bool, bool)`, `(u32, bool)`,
  `(bool, u64)` and the fuzz shape `((bool, bool),)` in custom MIR.
  Without the fix it fails (`!p.1 as u8` is 255, and `3 * 255` overflows).
- Seed 18889 is in `FUZZ_REGRESS` (`harness/gate.py`).
