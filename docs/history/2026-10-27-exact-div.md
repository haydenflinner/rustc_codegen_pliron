# The extra `umulh`s are coldargs zeros, not exact division

2026-10-27-code-size found 1,416 more `umulh` in pliron's regex-syntax
object than in LLVM's (`-O -Ccodegen-units=1`, aarch64). The guess was
`(end - start) / size_of::<T>()`: LLVM knows that division is exact and
multiplies by a modular inverse, while Cranelift uses the magic-number
`umulh`. **That guess is wrong.** Almost all of them are the disguised
zero that `coldargs` builds.

## Classification

The table classifies each `umulh` by what feeds it and what uses it in
the objdump listing:

| kind | pliron | LLVM |
|---|---|---|
| coldargs zero: `umulh z, x, xZ` where `xZ` is 0, used only by `add a, a, z` before a `bl` | 1,396 | 0 |
| magic-number division, then `lsr` (element counts: `Drain`/`IntoIter` len, `(end-start)/{24,48,160}`, sort) | 17 | 4 |
| `checked_mul` overflow test (`mul` + `umulh` + `cmp #0`) | 6 | 7 |
| i128 multiply (`umulh` + `madd` chains) | 8 | 0 |
| total | 1,427 | 11 |

`coldargs` (clifpeep.rs) moves the fixed ABI-register use of a cold
call's arg out of the hot region. It rebinds each hot int arg as
`iadd x, z`. `z = umulhi x, 0` is a zero that the egraph can't prove is
zero, so it can't fold the `iadd` back into `x`. On aarch64 that costs a
`umulh` per cold block and type, plus an `add` per arg. The `iconst 0`
is GVN'd, so it often stays live through the whole function in a
callee-saved register (`mov x27, #0` in `extract_concat`'s prologue).
Most of these sit in landing pads and in panic and `dealloc` calls:
`umulh x2, x0, x27; add x0, x0, x2; bl _Unwind_Resume`.

Exact division is real but small: 17 against LLVM's 4, so about 13
`umulh` in this crate. It is not worth a transform yet.

## Fix: `PLIRON_COLDCOPY=1` (default off)

- `coldargs(f, copy)` builds the zero as `umulhi 0, 1` when the flag is
  on. The `1` keeps this form apart from the default `umulhi x, 0`,
  including the case where `x` is itself a zero.
- Vendored aarch64 ISLE (`iadd_coldcopy_*`): `iadd x, (umulhi 0, 1)`
  lowers to a 64-bit `Inst::Mov` into a fresh vreg. That is a real copy,
  so the call's fixed-register constraint stays at the cold site. The
  `umulhi` and its constants have no lowered uses and emit nothing.
  `umulhi_zero` lowers a bare `umulhi 0, 1` (a rebind that a later pass
  folded to `z`) to `mov #0`.
- Emission drops a 64-bit `mov` whose source and destination are the
  same register. This is unconditional, because it is a no-op removal.
  It removes 27 such moves (`mov x2, x2`) from the default build too,
  which changes nothing else.
- Other ISAs have no rule. They lower `umulhi 0, 1` exactly like the old
  form, at the same cost. wasm skips `coldargs`.

## Numbers (regex-syntax, release dylib)

| | `__text` B | insns | `umulh` | `add` | `[sp]` loads | `[sp]` stores |
|---|---|---|---|---|---|---|
| LLVM | 184,752 | 46,188 | 11 | 4,217 | 3,420 | 2,934 |
| pliron, flag off | 401,680 | 99,414 | 1,427 | 7,277 | 16,537 | 9,051 |
| `PLIRON_COLDARG=0` | 388,880 | 96,171 | 31 | 5,182 | | |
| `PLIRON_COLDCOPY=1` | 386,512 | 95,577 | 31 | 5,169 | 15,339 | 8,796 |

With the flag, `__text` shrinks by 15.2 KB (3.8%) and the build has
3,837 fewer instructions. ALU instructions drop by 3,568 and stack
traffic by 1,453, against 1,164 more `mov`s. The flag is also smaller
than turning `coldargs` off, and it keeps the hot-loop benefit that
`coldargs` exists for. The spill drop comes mostly from freeing the
callee-saved register that held the zero.

## Tests

- `pliron-clif-opt/tests/coldcopy.rs` (aarch64 macOS) compiles a function
  whose cold `call_indirect` has 12 args: i64/i32/i16/i8, repeated args,
  a hot zero, sext/uext narrow args and 4 stack args. It checks that the
  copy form has no `umulh` and no self-move, and that the default form
  still has its `umulh`. It then runs both in a MAP_JIT page with
  boundary inputs and checks that the Rust recorder sees identical,
  expected args. It also checks the bare `umulhi 0, 1` lowering
  (`mov #0`, runs as identity under `bxor`).
- `filetests/coldargs_copy.clif`: the CLIF shape.
- `test.sh` `coldcopy`: cold calls with every int width, boundary
  constants, zeros, pointers, stack args and bounds-check panics. Built
  with `PLIRON_COLDCOPY=1`, its output is diffed against stock rustc's.

Follow-ups: flip the default after the corpus is clean; add an x64 rule
(there `umulhi` is a `mul` that pins rax and rdx, so the gain is larger);
exact division for the remaining 13 element-count `umulh`s.
