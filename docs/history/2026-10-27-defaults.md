# Defaults: the stack-slot, inliner and memory flags turn on

After a week of default-off flags (`AGENTS.md`: new transforms land off
and keep a kill switch), the set measured together turns on.

## What turns on

`pliron_cfg::DEFAULT_ON`: an unset variable reads as `1`, and `=0` turns it
off.

- Slot merging: `SLOTMERGE_MARK`, `SM_MARKFLOW`, `SM_COALESCE`,
  `SM_PRECISE`, `SM_DROPNC`, `SM_BYSIZE`, `SM_FLOWIV`, `SM_AFTERKILL`,
  `SM_STARTS`, `SM_STARTONLY`, `SM_ESCFLOW`, `SM_COALCALL`, `NOCAP_FIELDS`,
  `NOCAP_CALLEE`
  (2026-10-25-slot-coloring, 2026-10-26-slot-interference).
- Inliner: `INLINE_RESUME_DOM`, `INLINE_RESUME_HOIST`, `INLINE_ONCE1`,
  `INLINE_RECSTACK`, `INLINE_SCCLIMIT` (2026-10-26-inline-recursion).
- Memory: `DEADFREE` (2026-10-26-memory).
- `REMAT_SADDR`, read inside the vendored Cranelift, now defaults the same
  way (on unless `=0`).

Stays off:
- `XFACTS_ALL`: holds every CGU's IR until the LTO barrier (+2 GB on
  the biggest stage-2 crates), breaks determinism R2 (serial and pooled
  builds differ), and needed two LTO fixes this week.
- `INLINE_COLD` grows code. `INLINE_DUPCOST` alone made stack worse,
  and neither adds anything on top of the set.
- `CGU_INFLIGHT` is a memory-versus-time knob, not a default.

## Kill switches by construction

The flags were read in three ways: `env_is(X, "1")`, `env_set(X)` (presence,
for `SLOTMERGE_MARK`, under which `=0` would have counted as on), and
`std::env::var` inside vendored Cranelift (`REMAT_SADDR`). Several were read
at more than one site (`SM_MARKFLOW` in three files). Flipping each site by
hand could leave a pass half on. Instead the defaults go into the parsed
config once, so every `env_is` site sees the same value. The three presence
reads became value reads, and the one read outside the config defaults the
same way. `X=0` therefore reaches every site with no separate test per
switch. A grep for the flags' `env_set` reads finds only diagnostics.
