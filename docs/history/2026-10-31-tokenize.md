# tokenize: the 1.23x was noise; LTUNDEF's zeros cost 15% in a small loop

## The card number

The 2026-10-30 card had native `tokenize` at 1.229x LLVM. Rerun on the same
tip (load 5-8):

- `bench/run.sh tokenize`: 1.011x.
- `bench/run.sh` (all kernels): 1.006x.
- A standalone copy of the kernel (`s.split_whitespace().count()` x10 over
  400 KB), `rustc -O`, 9 interleaved rounds: 1.033x.

`harness/parity.py` runs criterion once, with every LLVM kernel first and
every pliron kernel after, so a load spike during the second half shows up
as a pliron regression. The 1.229 was one of those.

## What did move tokenize

The 10-27 runs had tokenize at 0.66-0.87x; the 10-29 defaults flip
(2026-10-27-batch.md) saw it go to ~1.0x and pointed at `LTUNDEF`, which
was left out of that flip and then turned on with the MEM movers
(`e63e878`).

Static bisect on the standalone kernel: of the default-on flags, only
`LTUNDEF`, `CMP3`, `NARROWEXT`, `DEADFREE` and one layout group
(`EDGEMERGE`/`EPIMERGE`/`COLDCOPY`/`REDUCIBLE`) change `k_tokenize`'s code.
Timed interleaved (median of 9, ms):

| build | ms | / LLVM |
|---|---|---|
| LLVM | 5.698 | 1.000 |
| defaults | 5.885 | 1.033 |
| `LTUNDEF=0` | 5.019 | **0.881** |
| `CMP3=0` | 5.882 | 1.032 |
| layout group `=0` | 5.882 | 1.032 |
| `DEADFREE=0` | 5.885 | 1.033 |
| `NARROWEXT=0` | 5.883 | 1.032 |

`LTUNDEF` has two halves: SROA's single-store forwarding ignores lifetime
markers (where syn's size win came from, 2026-10-27-spills.md), and
lowering redefines a promoted local's variables as zero at each marker.
Zeros at `lifetime.start` only reproduce the whole loss; zeros at
`lifetime.end` only are worse (1.068x); no zeros with the SROA half kept
gives code identical to `LTUNDEF=0` (0.884x). Marker bisect: the five
markers of the per-character `Option<(usize, char)>` from
`CharIndices::next` (3 variables each) do it together.

Why: `CharIndices::next` returns `None` by writing only the char niche. With
the zero, the `Option<(usize, char)>` join gets `(0, -1)` from the end edge
and `(idx, byte)` from the decode edges, and the merge block tests
`char == -1` on every character. Without it the end edge leaves the join
before the test and the ASCII path is 13 instructions with 2 taken branches
per character instead of 14 with 3 (`b.ne`, `tbz` into the join, `b` back).
The divergence starts in the first lowering (738 vs 717 CLIF insts) and the
jump threader converges after 5 rounds instead of 8; there is no single
pass to patch.

## Where the zeros still pay

Turning the zeros off everywhere (interleaved, 3 rounds of every kernel):
tokenize 0.863x, every other kernel within 1.5% except `varint_postcard`
1.058x. `sum_postcard` (serde's inlined decode loop) gets a 64-byte spill
area and 71 more instructions without them; its benefit is spread over
60+ markers. That loop has no calls, so "loops with a call" alone doesn't
keep it. What separates the two is how many promoted variables the loop
restarts: 18 distinct ones in tokenize's loop (outer and inner, one SCC),
58 in sum_postcard's. Carried values only cost spills once they exceed the
registers (28 allocatable integer registers on aarch64).

`harness/frames.py` (regex-syntax, 1 CGU, 327 shared functions): 54,736 B
with zeros everywhere, 54,976 B with none (1.124x vs 1.129x LLVM).
`tests/spills`'s `ltu_visit` (the NestLimiter shape the zeros were built
for, 912 -> 416 B on 10-27) is the same either way now; later slot passes
cover it.

## Change

Lowering emits the zeros only in blocks of a CFG cycle (SCC, including
invoke pad edges) that contains a call or whose markers restart at least
24 distinct promoted variables (`lt_loop_blocks`, `LT_PRESSURE`).
`PLIRON_LTUNDEF_PRESSURE=<n>` overrides the threshold and
`PLIRON_LTUNDEF_ALL=1` restores zeros at every marker (byte-identical
`k_tokenize` to the old default). tokenize gets the no-zeros code;
`sum_postcard` keeps the zeros' code.

## Result

Interleaved, 3 rounds of every kernel, old default vs this change (ms,
medians): tokenize 5.955 -> 5.088 (0.854x), varint_postcard 5.210 ->
5.209, every other kernel within 0.5%; geomean 0.991. Against LLVM that puts
tokenize at about 0.86-0.88x. regex-syntax frames: 54,784 B (1.125x LLVM;
zeros everywhere 54,736 B, none 54,976 B).
