# 2026-11-11 — XCGU_SIZE=150 ICE fix, punroll KEXIT A/B, decompress census

## jumpthread stale-base ICE (aaec1ed)

`PLIRON_XCGU_SIZE=150` crashed `opt cgu.N` on pulldown-cmark:
`dfg.rs:325 index out of bounds: len 38248, index 4294967295`
(`u32::MAX` = `Value::reserved_value()`).

Bisect (`fnbisect` over the cmark build, then `PLIRON_TRACE=pliron::step`
span closes) showed the panic inside `jumpthread::NonNull::is_deps_at`
via `is_m_at` ← `fold_null_tests` ← `s_jtround`. The culprit functions
were the 6 callers that had received an xcgu copy of
`scalar_iterate_special_bytes`.

Root cause: `NonNull::site_derived` resolved recorded
`site_facts.derived` bases with `resolve_aliases`. A recorded base whose
alias chain ends at the reserved slot (the base's def was deleted/merged
by an earlier step) panicked. Fix: `try_resolve_aliases` + skip stale
sites; `RegionNN::holds`'s `derived` walk hardened the same way — a
tombstoned base makes the fact unusable, not the query unanswerable.
Same convention `derived_base` already used for tombstones.

Not xcgu-specific — any stale site/derived base could hit it; size-150
copies just made it likely. Gate 94/94, fuzz 399/399; all 8 held-out
benches build at XCGU_SIZE=150 after the fix.

## punroll KEXIT (8b80588, opt-in)

`montgomery` (blind-sig) grew 4 loops 8x each — decrementing/store and
swap loops keeping a data-dependent exit per copy (`icmp`+`brif` each).
The latch test amortizes; the kept exits don't. `run_loop`'s
`unroll_width` is body-size only — no kept-exit term (peel path has
`16/exits`, counted path had nothing).

New opt-in `PLIRON_PUNROLL_KEXIT=N`: `k = min(k, N/(kept+1))`.

- KEXIT=8 (k≤4 @1 exit): geomean 1.002 — compression 0.971*,
  json 1.022*, blind-sig 0.996.
- KEXIT=4 (k≤2 @1 exit): geomean 1.000 — blind-sig 0.937, protobuf
  0.982*, but regex 1.069*, json 1.046*.

Kept exits aren't uniformly bad — some loops complete their copies
profitably. Left opt-in, same status as `PUNROLL_FNMAX`.

## XCGU_SIZE=64/80 A/B (same cap question, smaller bump)

`try_allocate_in` is `size_estimate=62` vs the 50 cap: in the
html-rewriter build every callsite logged `has_body=false` →
`reject (ineligible)` (37 `bl` sites; LLVM has 3). The cap is the
single reason — it is an `inlined=false` single-home item, so
`XCGU_INLINED`'s size exemption does not apply.

- `SIZE=80`: html-rewriter −1041 static insns, `bl try_allocate_in`
  37→16; runtime 0.982→0.996 trending. Suite geomean **0.998** —
  blake3 0.975, regex 0.945 win; blind-sig 1.043*, protobuf 1.042
  (wide CI) loss.
- `SIZE=64`: html-rewriter **0.960***, blind-sig **1.048*** — the
  regression is intrinsic to copying more, not the 62–80 band
  (812 new copies blind-sig-side, each thin). Montgomery unchanged
  in both.
- Same verdict as SIZE=150: per-workload tradeoff, stays opt-in.

## html-rewriter whole-binary buckets (pliron 212,869 vs LLVM 144,576)

- `mov` +15.6K: arg-reg writes 22.5K vs 10.1K (+12.5K — call plumbing
  at +2K `bl` sites + per-call shuffling; ~8K of the gap); rest is
  edge/intra-block regalloc reconciliation.
- `b` +9.5K, `nop` +1.5K — block fragmentation (~1.4x branch targets,
  ~5x loop-head pads).
- `add` +6.7K — mostly pointer-as-value (struct/call plumbing), NOT
  missed amodes: `add` directly feeding a memop's address is only
  +516 (imm) / +742 (reg) of it.
- `cmp` +5.6K, `cset` +1.2K, `csel` +0.7K — check/compare residue.
- `stur`/`ldur` +7K — spill traffic, downstream of live-range count.
- `udf` +792 — dead trap tails we keep (cold, size-only).

## montgomery decomposition (861 vs 309 lines)

Inner carry chain already matches LLVM (11 insns, same
`umulh/mul/adds/cinc`). The 2x lives in:

- `ne 1..8` linear dispatch to `block79(k)` (match len → specialized
  loop; canon-args shape bittab doesn't reach — it formed late).
- Tightening-bound chains: `icmp ult v285, len-k` for k=1..8 — same
  LHS vs progressively stricter bound feeding one panic edge; the
  last check implies the rest (needs implication analysis, not the
  &&-fold — ccmp would keep both compares).
- Per-operand two-arm dispatch: `icmp uge len,5; brif` then
  `icmp eq v5, <field|len>` per arm — `SmallVec`-style inline/spill
  probes, ~10 insns × several sites.
- `edgesink` +37 blocks (+8 insts): 586 CLIF insts / 174 blocks =
  3.4 inst/blk, then 861 machine (1.47x expansion — edge
  reconciliation dominates).
- `bcheck` fired +0/+0 — the Vec-limb loops' checks stay (bcheck's
  MAX_CHECKS / non-counted-trip limits again), which also blocks
  `ivptr`/`ivdown` (index stays live in checks → not exit-only).

## montgomery's `ne`-chain: memory-carried IV, not a switch

The block635-643 `icmp ne v2503, k` chain (k=1..8) is a punroll'd
`while i>=1 { i-=1 }` countdown where `i` lives in a memory slot
(`v1888` — a pointer *value* stored to, not an `explicit_slot`, so
`slotprom` can't promote it). Each copy: `iadd v2503,-k; store v1888`
+ `load v0+40` (len, reloadable but unprovable — the store may alias
in CLIF's view) + `icmp ne v2503,k; brif`. LLVM register-carries the
IV (`subs;b.ne` ~3 insns); ours is ~5 insns/copy + edge blocks.
Fix class: memory-IV promotion (prove the slot's pointer is a
non-escaping local address) or punroll emitting register-carried
countdowns — neither is a small patch.
