# pliron-inc-ld: incremental Mach-O linker — first results

Continues the round-trip work in
[`2026-11-06-round-trip-parity.md`](2026-11-06-round-trip-parity.md),
which identified the system link (~0.2 s) as the floor no backend owns
and called for "a specialised path (incremental/patch link reusing the
prior image)". `tools/pliron-inc-ld` is that path: a `-Clinker`
drop-in that records a manifest at baseline and splices only changed
leaf `.o` inputs into the previous image on later links.

## Measured

`harness/rtt.py --runs 5 --linker tools/pliron-inc-ld/target/release/pliron-inc-ld`,
aarch64-apple-darwin, release dylib, 281-crate egui/wgpu/winit tree
(deps cached). Medians, wall-time `cargo build` of one rep:

| shape | stock | pliron | incld | incld/stock |
|---|---|---|---|---|
| thin (marker edit = relink floor) | 0.409 s | 0.461 s | **0.238 s** | **0.582** |
| large (real codegen + relink) | 0.670 s | 0.674 s | 0.627 s | 0.937 |

The thin shape is essentially `cargo overhead + link`: splicing cuts
the ~0.2 s system `ld` to ~10-110 ms depending on how much moved.
Large is codegen-bound, so the link share is smaller.

## What makes it ASLR-safe

The naive "append to headerpad" prototype produced binaries that ran
under `lldb` (ASLR off) and died on direct exec: appended pointer
slots get no dyld fixup coverage. Fixes that landed:

- **Rebase-blob extension at EOF.** dyld requires rebase opcodes
  inside `__LINKEDIT`'s file range — even the unmodified blob fails
  when copied to a `__TEXT` pad ("overlap of start of LINKEDIT",
  "terminated early at offset N"). The linker copies the blob, trims
  its `DONE` + pad zeros, appends `SET_SEG_AND_OFFSET` /
  `ADD_ADDR_ULEB` / `DO_REBASE` per appended pointer slot (a missing
  `ADD_ADDR` produced gaps read as opcodes — the "offset 1" dyld
  error), terminates, writes at EOF, grows `__LINKEDIT`'s
  filesize/vmsize, and repoints `LC_DYLD_INFO_ONLY`. The code
  signature stays put, so in-process adhoc resign still works.
- **Writable `__DATA,__incpad` pad.** Once the stream parsed, dyld
  crashed inside `applyFixups`: it writes rebased pointers with a
  plain `str`, so targets must be in a writable segment — `__TEXT`
  pads cannot host pointer data. Baseline injects
  `-sectcreate __DATA __incpad <4MB sparse>` (survives `-dead_strip`,
  verified empirically) and Phase 2 routes `__DATA*`-seg and
  pointer-bearing sections there.
- **In-place section patching.** Same-size changed sections are
  rewritten at their existing address, keeping dyld fixup coverage —
  preferable to appending whenever it applies.
- **Reloc-slot fingerprints.** A dead-stripped or all-pointer section
  (e.g. a `__DATA,__const` table whose every byte is a reloc target)
  can't be content-matched into the image. The manifest records each
  section's reloc *slot values* (pointer targets under the old
  layout); on relink, the new object's same slots are resolved under
  the old layout and matched to find placement.
- **`-dead_strip` stripped at baseline.** ld's dead-strip shuffled a
  6000-entry descriptor table to ~1300 entries, breaking contiguity.
  Keeping it off at baseline means `.o` sections land contiguous.
- **Idempotent repatching.** GOT-relaxed sites (`adrp+ldr` →
  `adrp+add`) are already `add` on the next round — `apply` accepts
  either instruction shape.
- **PAGE21/PAGEOFF12 encodings.** Clear masks preserve rd ([4:0]);
  PAGEOFF12's imm12 scale comes from the instruction's size bits
  [31:30], not `r_length` (same fix the hot loader needed).

## Verification

Five successive edit→splice→direct-run rounds on the 9.7 MB `large`
binary under normal PIE + ASLR: all correct, `verify: ok` — including
a 192 KB pointer table landing in the `__DATA` pad with real rebase
coverage.

## Caveats / next

- aarch64-apple-darwin only, and only classic `LC_DYLD_INFO(_ONLY)`
  rebase fixups (chained-fixup binaries fall back to `ld`).
- Unwinding metadata is not updated for appended code.
- The manifest is per-output-path; `cargo clean` rebaselines.
- Splice time is ~10-110 ms; the wins compound with `PLIRON_HOT`
  (which needs no relink at all).
