# Crate-wide capture summaries (`PLIRON_NOCAPSUM`, opt-in) — 2026-11-23

## Why

html's `SelectorMatchingVm::exec_without_attrs` copies a 144-byte struct
onto the stack and reads fields back from the copy, where LLVM reads them
from the source (`selectors_vm/stack.rs:196-197`, about 0.5-0.7% of html's
samples). memcpyopt's `srcfwd` refuses: the source "may be captured".
`PLIRON_TRACE=pliron::memcpyopt=debug` now names the use that decided it
(891a9a69): `ExecutionCtx::add_execution_branch`. Its `self` reaches
`RawVec::grow_one`, then `RawVecInner::finish_grow`, and also hashbrown's
`reserve_rehash`, each in another CGU. xfacts adopts only facts each CGU
solved on its own, so a chain of cross-CGU hops never resolves.

## What

- `nocapture` (under `PLIRON_NOCAPSUM=1`) also runs a summary form of
  its Datalog program (`CapSumProg`). A call to a callee with no body
  in the CGU is not a capture but an edge
  `dep(f, i, callee, k)`. Edges are followed through the bodied
  callees, so each param ends as `Captured` or as the set of bodiless
  callee params it reaches.
- Summaries are published with the CGU's other facts. Copies merge per
  param: captured in any copy means captured, and edges union.
- Behind rustc's thin-local LTO barrier (`PLIRON_XFACTS_ALL=1`), the
  first `facts_adopt_all` solves every summary once (`solve_capsum`).
  The solve is a least fixpoint of captured (copy, param) pairs over the
  edges. An edge to a symbol no CGU summarized under that type captures.
  Bodiless declarations take the solved set, and `nocap3` reruns with it
  (then `srcfwd2`).

Unit tests: `nocapture::capsum_tests` (a three-hop chain, imports and
cycles, the merge).

## Result: no win, kept opt-in

The solve resolves the cross-CGU hops, but `add_execution_branch` still
captures its `self` for two local reasons:

1. A pointer derived from `self` (the hash builder inside hashbrown's
   `make_hasher` closure) is stored into a stack slot, and the slot goes to
   `reserve_rehash`. A store of a derived pointer counts as a capture
   unless the slot never leaves the function. Freeing it needs
   "pointee" capture facts: what a callee does with pointers stored in
   the memory it is given. LLVM's `captures(none)` does not model that
   either.
2. A block param joins a `self`-derived pointer with others and flows into
   the indirect `match_handler(..)` call (flow imprecision).

macOS retired instructions, one `ab.py` run each, 7 rounds, against the
defaults:

| program | `XFACTS_ALL` | + `NOCAPSUM` |
|---|---|---|
| html | +1.3% | +0.9% |
| regex | +0.1% | +0.8% |
| compression | +0.1% | +0.2% |
| json | +0.0% | +0.1% |

A 3-round pass over all eight changed the code of seven of them. Its
regex -1.4% was noise: the default build read 65.11M in one run and
63.58M in the next. Compare sides within one `ab.py` run only.

## Depth-1 capture facts (`PLIRON_NOCAP_DEEP`, opt-in), same day

Taken up again at Hayden's call. Capture now runs over nodes (`CapNode`):
node `2i` is param `i`, and node `2i+1` is the set of pointers loaded
straight out of its memory (depth 1).

- A pointer stored into a stack slot whose address goes only to loads
  and call arguments (`slot_calls`: direct calls, or indirect ones with
  resolved callees) is at depth 1 of that slot. It is captured only if
  a callee that gets the slot captures its depth-1 pointers (`slotarg`).
- `memcpy`/`memmove` out of a param's memory captures depth 1.
- Depth 2 (the heap buffer behind a table pointer, which goes to
  `__rust_dealloc`) is not tracked, and answers nothing about depths 0
  and 1.
- The node program's store -> load flows through frame slots compare
  byte ranges, pairwise up to 256 loads (`slot_flows`). Otherwise
  hashbrown's scope guard made the new table's control pointer "derived
  from" `&alloc`, which sits next to it in the guard.
- Summaries (`PLIRON_NOCAPSUM`) are per node. The solve is unchanged.
  Adoption fills `nocapture` from even nodes and `deepnocap` from odd
  ones.

The default `Capture` program and its inputs are unchanged: the html,
regex and compression `__text` is byte-identical to before. Tests:
`deep_slot_to_a_reader_does_not_capture` (passes only with the knob),
`deep_slot_to_a_keeper_captures` and
`deep_slot_to_an_unknown_callee_captures`. Gate passed.

## Where the html chain stands

`reserve_rehash` (hashbrown, inlined `reserve_rehash_inner`): `devirt`
resolves the `dyn Fn` hasher calls before `nocap2`, the scope guard's
slot now passes, and the stores of the new table into `self` no longer
inherit the guard's `&alloc`. They still inherit it through
`mem::swap`'s word loop (`swap_nonoverlapping`). Its index is a counter
loaded from a slot, so the load's offset is unknown and overlaps
`&alloc` at offset 0. rustc emits `ptr.add(i)` as `gep inbounds nuw`,
and `nuw` alone would put every access at or past the guard's value
field. Our builder does not override `inbounds_nuw_gep`, so the flag is
lost. Next: record it (a per-op side table the inliner's clone has to
carry) and use it in `slot_off` as a lower bound. After that, the
remaining blockers are `add_execution_branch`'s closure slots (indirect
`dyn FnMut` probe calls) and the `grow_one -> finish_grow` chain, which
the solve already resolves.

## Keeping `nuw`, depth 2, constant callees, frozen borrows (same evening)

- **`nuw` survives lowering.** `Builder::inbounds_nuw_gep` (rustc's
  `ptr.add`) sets the GEP op's `NUW` no-wrap flag, an op attribute
  that travels with clones. `inbounds` stays in `State::inbounds`, and
  nothing else reads the new flag, so default code is byte-identical
  (html, regex, compression). `slot_off` uses it: a `nuw` GEP with a
  variable index adds at least its constant part, so `mem::swap`'s word
  loop over hashbrown's scope guard no longer overlaps the guard's
  `&alloc`. **`reserve_rehash` no longer captures its table** (node 0
  free).
- **Depth 2** (`DEPTHS = 3`, node `3i + d`). If a node is captured,
  every deeper one is. `slot_calls` follows a slot's address stored
  into another slot that has no loads, so the stored pointer sits at
  depth 2 of what the call gets. That is hashbrown's `find` probe
  closure holding `&mut equivalent_key(k)`, which the inliner turns
  down (613 ops, cost 853 against 360). **`Stack::build_state` no
  longer captures `name`.** Test `deep_nested_slots`.
- **Constant callees** (`helpers::const_callees`): an indirect call whose
  callee is a constant function address, or a join of several through
  block params (`bailout`'s recovery functions), reads those functions'
  facts, in `nocapture` and in `srcfwd`'s capture walk. Such a callee
  appears when `constload2` folds a vtable slot after the one `devirt`
  round. `PLIRON_DEVIRT_ROUNDS=<n>` (default 1) repeats the round while
  it finds sites, but on html the site `devirt` resolves is then
  refused by the inliner on cost.
- **Frozen borrows in `srcfwd`** (`PLIRON_SRCFWD_RO=1`, opt-in): a call
  operand rustc marks `readonly` + `noalias` (a frozen `&T`, or a
  by-value copy the callee never writes) is a read, not a capture.
  Writing through a kept copy of a shared borrow is UB. lol_html's
  compiled selector matchers get `&ctx.stack_item.local_name` through
  a `dyn Fn` that no analysis can resolve.

With all four knobs (`XFACTS_ALL`, `NOCAPSUM`, `NOCAP_DEEP`,
`SRCFWD_RO`), `exec_without_attrs`' stage-B `srcfwd` no longer sees
its source as captured. It now stops at drop glue on `ctx`'s fields
(`StackItem`, its `Vec`s, a `RawTable`), which count as writes on a
path from the copy to a read. They are most likely bailout and unwind
paths that a drop flag separates from the reads. Making the walk aware
of drop flags is the next step.

macOS retired instructions, 7 rounds (load average about 30 from other
work, so cycles are noise), against the defaults:

| program | `XFACTS_ALL` | all four | `SRCFWD_RO` alone |
|---|---|---|---|
| html | +0.7% | +0.6% | +0.4% |
| regex | +0.1% | +0.3% | -0.2% |
| compression | -1.0% | -1.3% | -1.2% |
| json | -0.2% | +0.1% | +0.2% |

`SRCFWD_RO` is a clear compression win. html needs a per-function
look before any default.

## The copy goes (`PLIRON_SRCFWD_RANGES`, opt-in), and what it was worth

`srcfwd`'s write test treated drop glue on the temp as a write over all of
it, so an unwind chain dropping a moved value's fields one at a time
(`RawTable`, two `RawVec`s) "wrote" before "reading" the next field.
With `PLIRON_SRCFWD_RANGES=1`, a write conflicts only with a later read
whose bytes overlap, in temp coordinates. A drop covers its operand's
`arg_extent` (rustc's pointee size for `drop_in_place::<T>`), a load
its size, a memcpy its length. An unknown range overlaps everything,
and with more than 32 writes the old test applies. With all five knobs,
**`exec_without_attrs`' 144-byte copy is forwarded** in all four CGU
copies (`srcfwd: 144-byte temp reads param at +0: 1 copies, 30 reads`).

Worth, at load average about 5 (macOS instructions, 9 rounds): html
with four knobs -0.2%, with the copy removal also -0.2%. The copy was
worth less than its samples suggested (0.5-0.7%).

Which program got slower: none. On all eight, 7 rounds: blind-sig
+0.3%, blake3 +0.2%, regex +0.5%, html -0.3% (`SRCFWD_RO` alone html
-0.5%, the rest flat). blake3's `__text` is byte-identical in all three
builds, so 0.2% is this machine's noise between builds.
compression's earlier -1.2% with `SRCFWD_RO` came from a byte-identical
build: noise too. regex's cost sits in `Fsm::follow_epsilons` (+7.7%
self samples), whose code is instruction-for-instruction identical
between the builds: placement, from 47 other functions changing size
(256 bytes). The benchmark outputs match default on all seven
programs that print one. The gate passed. The knobs stay opt-in: they
are not worth defaults on these numbers, and XFACTS_ALL keeps its
memory cost.

## Free information we drop (survey)

From rustc's builder, unused today:

- `unchecked_{u,s,su}{add,sub,mul}` lower to plain arithmetic: no
  `nuw`/`nsw`.
- `unchecked_{u,s}trunc`: no `nuw`/`nsw` on trunc.
- `or_disjoint`: no `disjoint` (an add).
- `range_metadata` keeps only `0..=1`: enum tags, `char` and `NonZero`
  ranges go.
- `load`/`store` alignment (`_align`).
- `switch_with_weights` cold cases and `br_with_attrs` unroll hints.
