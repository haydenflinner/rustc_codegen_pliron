# 2026-10-30: cmp3 push-through read a param it was removing (seed 17028)

**Symptom.** Fuzz seed 17028 at `-O` ICEd: `cmp3 broke fn5: icmp.i8 ne v5042,
0: argument v5042 is not attached`. `PLIRON_CMP3=0` passed.

**Cause.** `push_through` turns the compares on a block param `p` into new
params computed on every incoming edge. For a loop header whose only use of
`p` was `c = icmp eq p, 0` and whose back edge passes `c`, the edge arg is
`c`, so the new per-edge query is `icmp eq c, 0`. `selord_icmp` collapses
that onto the operands of `c`, i.e. `icmp ne p, 0`, which reads `p` itself.
The self-loop guard only checked that no edge passes `p` directly. `p` was
then removed and the new compare kept a detached operand.

**Fix.** `try_push` bails when `p` is in the operand cone of any edge arg
(`reaches`, depth 8, 64-value budget; a blown budget also bails). Regression:
`loop_arg_reads_param` in `pliron-clif-opt/tests/cmp3.rs` (panics in the
verifier without the fix); seed 17028 is in the gate's `FUZZ_REGRESS`.
