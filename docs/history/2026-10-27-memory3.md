# Compile memory, part 3: `LOWERFREE` on wasm, a 16-byte op location

Follows docs/history/2026-10-27-memory2.md. The baseline everywhere below
is `F` = `PLIRON_LOWERFREE=1 PLIRON_JEARENA=1 PLIRON_CGU_ACAP=8` (default
off, being validated for default-on). Nothing here changes an output byte
(docs/determinism.md R3).

## 1. `LOWERFREE` for wasm

### Where the peak was

`PLIRON_LOWERFREE` released a CGU's pliron `Context` after phase (A) on
native only. The wasm emitter still read it after lowering, in three
places: `wsig` (declaring each function's waffle signature), and at the
very end of `emit_obj`, `link_section` (the `pliron.link` custom section:
function flags plus every data initializer's bytes and relocations) and
the `#[link_section]` custom sections. All three are pure functions of the
`Context` and the `State`, which lowering never mutates. So the `Context`
(for regex-wasm, 380k ops / 72k blocks after inlining: op arena 87 MB,
blocks 22, use links 24, op links 12) stayed resident through the CLIF
pipeline, the waffle translation, `winline`, compile and `wpeep`.

A second, smaller hold: `lower_clif_wasm` returns every function's
optimized CLIF in one `Vec`, and the translation loop iterated it by
`&mut`, so all of it lived until the function returned, after `emit_obj`.

### The change

- `wasm::lower_to_wasm_clif` takes the `CtxSlot` (owned in the pool, as
  for native). It declares the signatures and serializes a `ModTail`
  (link section, custom sections) from the `Context` first, then calls
  `lower_clif_wasm`, which now takes the slot and, under the flag,
  releases it between `start_jobs` and `finish_jobs`, as `lower_module`
  does. The stats line is the same `lowerfree <cgu>: pliron Context
  released after phase (A)`. `-g` keeps the `Context` (`st.dbg`), as on
  native.
- A wasm `FnJob` keeps its optimized CLIF (the emitter's input) but sheds
  its lowering-fact tables after the pipeline (`FnJob::shed_facts`, split
  out of `shed`).
- The translation loop consumes the CLIF by value, so each function's
  CLIF is dropped once translated, and the FuncId/DataId name tables go
  before `emit_obj`. This part is unconditional: it only shortens a
  lifetime. (Flags off, regex-wasm's peak is unchanged by it: 769 → 765
  MiB.)
- `run_jobs` is gone; both paths use `start_jobs`/`finish_jobs`.
- `PLIRON_MEM_MARK` marks at the end of phase (A) (`wasm-pA`), after the
  pipeline (`wasm-pB`), and after translate, `winline`, compile,
  `to_wasm_bytes` and `wpeep`.

## 2. A 16-byte operation location

`Operation` was 160 B (168 in its arena `RefCell`, 176 with the slot's
generation), and 48 of them were `loc: Location`: the enum carries
`Fused { metadata: Option<AttrObj>, locations: Vec<Location> }` inline.
rustc_codegen_pliron only ever stamps `Location::Unknown` and
`Location::Dbg(u32)` (`builder.rs`, `inline.rs`), so vendored pliron now
stores `CompactLoc { Unknown, Dbg(u32), Other(Box<Location>) }` (16 B,
asserted at compile time) on `Operation` and `BasicBlock`
(`location.rs`, `operation.rs`, `basic_block.rs`, all `PLIRON:`-marked).
`Located::loc()`/`set_loc()` convert, so no caller changes; `dbg_loc`
reads the inline index. An op slot goes 176 → 144 B, the block slot
shrinks the same way.

This is a representation change with no flag: there is no behavior to
switch, and every object is byte-identical (below).

Peak RSS and wall time with `F`, `lockf`-held, median of 3, lever 1
against lever 1 + this. Two runs: the first at load 40–50 (other agents'
gates), the second at load 20–35; §1's numbers were taken at a lower load
still, so the times are only comparable within a row.

| input | lever 1 (load 45) | + CompactLoc | lever 1 (load 25) | + CompactLoc |
|---|---|---|---|---|
| kernels | 194 MiB 0.40 s | 187 0.38 | 190 0.35 | 191 0.32 |
| kernels-wasm | 195 0.88 | 189 0.74 | 197 0.70 | 191 0.76 |
| regex-syntax | 486 2.29 | 491 2.23 | 480 1.96 | 481 1.94 |
| regex-wasm | 558 3.83 | 527 6.00 | 550 2.69 | 534 2.69 |
| syn | 1,076 7.93 | 1,054 6.78 | 1,118 3.73 | 1,077 4.27 |

About 3–4% where the IR dominates (syn −22/−41 MiB, regex-wasm −31/−16),
within noise elsewhere (regex-syntax's runs spread 464–511). Time is
unchanged where the load allows a reading; no `Box` is ever allocated,
since the backend stamps only the two inline shapes. Smaller than the
32 B × 1.7M ops estimate because the peak is set during inlining, before
`DEADFREE` frees, and much of it is not the op arena.

## Remaining levers

1. The wasm phase-(A) hump: the whole CGU's CLIF is produced while the
   `Context` is alive, and the optimized CLIF of every function is held
   until translation. Translating each function to waffle inside its
   pipeline job (on the pool) would replace CLIF by waffle bodies as jobs
   finish; the bodies themselves must stay until `winline`.
2. The barrier wait (memory2 §Remaining 2) is not reachable byte-identically:
   ordinal order decides the facts merge, so splitting or reordering the
   heaviest CGU changes output. Dropped.
3. Fewer ops after inlining; constants as separate ops.
