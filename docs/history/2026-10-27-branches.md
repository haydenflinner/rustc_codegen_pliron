# Branches: where pliron's extra unconditional `b`s come from

Follow-up to 2026-10-27-code-size. On regex-syntax (`-O
-Ccodegen-units=1 --emit=obj`, aarch64), pliron emits 6,023
intra-function `b`s and LLVM emits 2,217, so pliron has 3,806 more. Tail
calls (`b` to another symbol) are left out of these counts.

## Classes

Each intra-function `b` gets one class. The class depends on the block
that ends in the `b` and on the block it jumps to. Classes are checked in
the order of the list below the table, and a `b` gets the first class
that matches. Columns: LLVM, pliron before the fixes, pliron with both
flags on.

| class | LLVM | before | both flags |
|---|---|---|---|
| block of only regalloc edits (mov/spill/reload) + `b`, duplicates of an earlier identical one | — | 1,740 copies | ~0 |
| moves-only edge block, entered by fallthrough | 156 | 995 | 310 |
| moves-only edge block, entered from a jump table | 0 | 272 | 21 |
| moves-only edge block, entered by a conditional branch | 50 | 142 | 278 |
| backward `b` to a block that ends in a conditional branch | 253 | 1,630 | 1,356 |
| forward, other | 858 | 1,971 | 1,190 |
| to a return tail | 224 | 425 | 845 (shared epilogue) |
| `b.c X; b Y` with neither fallthrough | 384 | 325 | 527 |
| backward, other | 66 | 225 | 364 |
| chain (target is itself `b`) | 148 | 0 | 0 |
| `b` to the next insn | 16 | 2 | 1 |

The first row overlaps the edge-block rows. It counts blocks that end in
`b T` and hold only `mov`/`ldr`/`str [sp]` after a control insn, when an
earlier block in the same function has the same insns and the same `T`.
There are 1,740 such duplicates, which hold 4,198 insns.

1. **Duplicate edge blocks (largest).** Cranelift splits every critical
   edge, and a jump table gets one split edge per entry. regalloc2 puts the
   edge moves into the split block. rustc's drop and unwind code sends many
   edges into one merge block, and their split blocks often get identical
   edits. In `lift_common_prefix`, five copies of
   `ldur x8,[sp,#0x50]; ldur x27,[sp,#0x58]; b merge` sit back to back.
   LLVM's branch folder merges these tails.
2. **Layout of merges and loops.** The chained block order places a merge
   block after its first predecessor in RPO, and every other predecessor
   jumps back to it. Loops are not rotated. Static `b` counts are the same
   either way, so rotation only helps dynamically.
3. **Cold tail.** About 1,850 `b`s start in the cold region at the end of
   each function (LLVM: about 700). These are landing pads, drop calls and
   panic blocks that fan in to shared resume or panic blocks.
4. **Not a branch, but found here.** Every function has one epilogue per
   `return`: 709 return blocks share a suffix of 3 or more insns, 4,300
   insns in all. Also, 1,654 `udf` traps follow noreturn calls, where LLVM
   on Darwin emits 71 `brk`s in total. That is 6.6 KB of dead traps (not
   fixed here; it is a lowering change).

## Fixes (vendored Cranelift, both default off)

- `PLIRON_EDGEMERGE=1|2` (PLIRON_PATCH 66): `VCode::emit` keys each block
  that is only regalloc edits plus an operand-less jump by (edits,
  successor). The first block in emission order with a key is emitted. A
  later block with the same key (a dup) is not emitted, and
  `MachBuffer::alias_label` makes its label resolve to the first copy.
  Branches, including jump-table entries, resolve through the alias.
  MachBuffer's existing fold turns `b.c L; b dup; L:` into `b.!c canon`.
  `=2` merges every dup, which put `tokenize`'s hot `cbz; mov; mov; b`
  edge on a taken branch (+9%). `=1` keeps a hot dup that is its
  predecessor's fallthrough or that falls into its own successor; cold
  dups always merge.
- `PLIRON_EPIMERGE=1|2` (PLIRON_PATCH 67): the first merging `return`
  binds a label in front of its epilogue, and each later merging `return`
  jumps to that label. `=2` merges every epilogue of 3 or more insts.
  That made `fib` 8% slower: its base-case return is hot and has a 3-inst
  epilogue. `=1` merges only epilogues of 5 or more insts, plus any
  return in a cold block. This trades `ret` for `b`, so it cuts size, not
  branches.
- Composition: `PLIRON_EDGEDEDUP` (patch 63, the ALU agent) shares a
  br_table's split-edge blocks before lowering, so its blocks never reach
  VCode, and an alias can only name a block that is emitted. Both flags
  together, with `PLIRON_COLDCOPY` also on, pass `tests/edgemerge` and the
  gate and fuzz runs below.

`PLIRON_COLDCHAIN` was tried and dropped. It extended block chains into
cold successors so that cold blocks fall through to each other. With
EDGEMERGE also on, it added 108 `b`s. With chains only into single-pred
cold blocks, it added 112. Chaining pulls a cold successor away from a
cold predecessor that RPO had already put next to it.

## Numbers (regex-syntax, `-O -Ccodegen-units=1`, aarch64)

`branches` counts every `b*`/`cb*`/`tb*`/`ret`. With all flags off, the
object is byte-identical to the one built before the change.

| | `__text` | insns | branches | intra-fn `b` |
|---|---|---|---|---|
| LLVM | 184,752 | 46,188 | 7,337 | 2,217 |
| pliron, all off | 401,680 | 99,109 | 13,984 | 6,023 |
| EDGEDEDUP + COLDCOPY (the base for the rows below) | 380,752 | 93,821 | 13,392 | 5,427 |
| base + EDGEMERGE=1 | 372,336 | 91,684 | 12,675 | 4,710 |
| base + EDGEMERGE=2 | 367,056 | 90,429 | 12,264 | 4,299 |
| base + EPIMERGE=1 | 368,944 | 90,843 | 13,353 | 5,889 |
| base + EPIMERGE=2 | 367,376 | 90,445 | 13,344 | 6,053 |
| base + both =1 | 360,272 | 88,720 | 12,637 | 5,173 |
| base + both =2 | 353,552 | 87,061 | 12,217 | 4,926 |

Gains on top of EDGEDEDUP + COLDCOPY:

- EDGEMERGE=1: 717 fewer `b`s and 8.4 KB less `__text`.
- EDGEMERGE=2: 1,128 fewer `b`s and 13.7 KB less.
- EPIMERGE=1: 11.8 KB less.
- Both at `=1`: 20.5 KB less (5.4%).
- Both at `=2`: 27.2 KB less (7.1%).

Before EDGEDEDUP landed, EDGEMERGE=2 alone removed 1,716 `b`s and
20.4 KB. EDGEDEDUP already covers the jump-table share of that.

## Runtime (bench kernels, pliron base vs base + both =1)

All runs were under `heavy.lock`, but the machine was still loaded. In
the full A/B, single kernels swung by 30–40% between runs (`hashmap`,
`chars_*`, `sieve`, `strwork`), so only reruns and layout sweeps count.

- **Layout sweeps** (`bench/layout.sh`, 3 layouts per side, medians):
  - `tokenize`: 5.17 → 5.16 ms.
  - `hmget`: 12.68 → 12.68 ms.
  - `sortw`: 6.24 → 6.19 ms.
  - Spread within one side was ±2%.
- **Stable A/B kernels**, within ±1.5%: `arrayvec`, `eqbug`, `fib`
  (13.55 → 13.61 ms), `matmul`, `nbody`, `parse_only`, `varint`,
  `varint_postcard`.
- **Rerun of the noisy kernels**: the base and flagged binaries ran alternately, twice each
  (`sieve`, `strwork`, `chars_*`, `hashmap`, `contains_rng`, `iterw`,
  `eqbug`). Every on/off pair is within 3%, and the sign changes between
  rounds. Example: `sieve` 12.00/11.87 ms off vs 11.83/11.85 ms on. No
  regression is visible above the noise.

Before mode 1, both flags merged everything (mode 2). Under that setting,
`tokenize` was +9% and `fib` was +8%. Those two results are why mode 1
exists.

## Tests

- `tests/edgemerge` (`test.sh t_edgemerge`) covers flags off, mode 1 and
  mode 2.
- Fuzz seeds 10700:11000 passed 300 of 300, with an earlier merge-all
  build.
- Gate runs:
  - plain: passed under `heavy.lock`;
  - with `PLIRON_EDGEMERGE=1 PLIRON_EPIMERGE=1 PLIRON_EDGEDEDUP=1
    PLIRON_COLDCOPY=1`: passed, including `fuzzreg`, `debuginfo` and
    `edgemerge`. The coordinator cleared the lock queue for this run, so it
    ran nice'd and without the lock.
- After the rebase onto `PLIRON_JT_NARROW`, `tests/edgemerge` matches the
  stock output with `JT_NARROW=1 EDGEDEDUP=1` at every `PLIRON_JT_WIDTH`
  (1, 2, 4) in both modes. Deferred tables read entry offsets through
  `resolve_label_offset`, so they follow the aliases. A table whose arm
  is a merged block can get a lower `base`, which costs a wider entry.
  The `adr` range assert still guards correctness.
- `PLIRON_NORETTRAP` landed (8e88727) just before the push. A
  `noret_dead` block emits nothing, so EDGEMERGE never uses one as the
  copy others alias to, and never drops one as a dup. `tests/edgemerge`
  and `tests/noret` (at -O0, -O and panic=abort, against stock) pass with
  `NORETTRAP=1 JT_NARROW=1 EDGEDEDUP=1` and both modes. No gate ran after
  this last rebase: the 07:30 quiet window had started.
- regex-syntax with `JT_NARROW=1 EDGEDEDUP=1` and the new defaults
  (COLDCOPY, REMATCALL): `__text` is 374,192 B, and 353,840 B with both
  merges at `=1` (−20.4 KB). Intra-function `b`s drop from 5,424 to 5,171.

Scripts: `bcls2.py` (classes), `ce.py` (duplicate edge blocks),
`tgt.py` (target shapes), `tailm.py` (tail-merge potential), `meas.py`
(totals). They are in the session scratchpad and are not checked in.

## Left

- The remaining `b`s are mostly layout: backward jumps to merge and loop
  heads (+1,100) and the cold tail's fan-in. The fix there is a real
  chain-based placement (LLVM's MachineBlockPlacement with static branch
  probabilities), not a tweak to the succ pick.
- General tail merging of common suffixes, not just edit-only blocks:
  `tailm.py` finds about 260 more merges (900 insns) for `b` targets.
- Edge moves whose destination is dead on the other edge could go before
  the branch. That would empty the split block entirely.
- Drop the `udf` after noreturn calls (1,654 insns).
