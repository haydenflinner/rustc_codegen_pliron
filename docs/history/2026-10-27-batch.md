# Overnight 2026-10-27: validating and flipping the code-size and memory flags

Agents landed default-off flags overnight (see each flag's history doc).
This page records how each was validated as a default, and why some stay
off.

## Batch 1: `LTUNDEF`, `REMATCALL`, `NARROWEXT`, `EDGEDEDUP`

| check | `LTUNDEF` | `REMATCALL` | `NARROWEXT` | `EDGEDEDUP` |
|---|---|---|---|---|
| stage 2 built with it, repros pass | yes | yes | yes | yes |
| stage-2 UI, no stage-2-only failures | yes | yes | yes | yes |
| fuzz 12000–12399 | (not run) | pass | **seed 12309 miscompiles** | pass |
| crates tier 1 | (not run) | pass | **regex-automata: 4 tests fail** | pass |
| peak RSS, syn | **+17%** | neutral | neutral | neutral |

The stage-2 build and the UI run had all four flags on together, plus
`COLDCOPY` (default since 644b4db). UI: 21,715 pass, 54 fail, and all 54 also
fail with the LLVM-built stage 1. Under the overnight load the suite took
66 min.

- `NARROWEXT`: seed 12309 gives a wrong hash with the flag alone. The UI
  suite didn't catch it. Off until fixed.
- `LTUNDEF`: on syn, peak RSS goes from 1,737–1,808 MiB to 2,086–2,132.
  On the parity card that costs about 1.1 overall points, against about
  +0.5 from its size and stack gains. Off until its memory cost is fixed.
- Fuzz and crates ran with REMATCALL, NARROWEXT and EDGEDEDUP together.
  Rerun per flag, both failures come from NARROWEXT alone: regex-automata
  passes 723/723 with REMATCALL alone and with EDGEDEDUP alone, and seed
  12309 passes with either. The UI suite caught neither failure.

**Flipped:** `REMATCALL` (fcef713). Its read site is in vendored Cranelift
(`std::env`), so its default changed there as well: on unless `=0`.
**Waiting on a quiet A/B:** `EDGEDEDUP`. Its bench run moved tokenize
0.83 → 0.89 and varint 0.95 → 1.02 together with NARROWEXT, while LLVM's
own medians moved up to 20%.
