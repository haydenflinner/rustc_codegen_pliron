# 2026-11-20: loop strength reduction onto a pointer IV (`ivsr`), SLOTCOMB cap

## The gap

`rust-compression`'s hottest line after SLOTCOMB is brotli `hq.rs:517`
(`EvaluateNode` inlined into `BrotliCreateHqZopfliBackwardReferences`):
`nodes[pos + 1]` with 20-byte nodes. Ours per trip:
`add x0, x20, #1; ldr x1, [sp, #9512]; madd x6, x0, x17, x1; ldur w0, [x6]`
(base spilled, reloaded every trip). LLVM: `add x8, x19, x25`, a pointer IV.
Neither `lsr` (rebases onto an existing pointer IV) nor `ivptr` (index-rebuilt
pointer params) creates a new one.

## `ivsr` (`PLIRON_IVSR=1`, opt-in)

New header parameter `p = base + S*i + k0` per `(i, base, S)`; entry edges
compute it, back edges pass `p + S*c`, addresses become `p + (k - k0)`.

Rules found by measuring (each one a loss without it):

- **Address already carried.** lol_html's selector VM passes
  `base + 120*(i + 1)` back to the header: replacing it gave a second
  register for the same pointer (weighted static +5.3k). Values passed on
  the back edge are skipped, as are loops with a parameter stepping by `S*c`.
- **Every trip.** A group needs an address in a block dominating each latch.
- **Not innermost-only.** `SplitByteVector` (1040-byte histograms, an
  inner loop per trip) is a static loss, but restricting to innermost loops
  drops the per-position loop, which contains inlined inner loops.
- **Loop size does not separate wins from losses.** `UpdateNodes`' win is a
  19-instruction loop; html's losing attribute loops are 6 and 18. The
  floor stays a knob (`PLIRON_IVSR_MIN`, default 0).

aarch64's `madd` makes `base + i*S` one instruction, so `ivsr` only pays
where the base or the stride were under register pressure. Without a
pressure estimate at CLIF level this stays opt-in.

## `bump_hoist` and the IV (`PLIRON_BUMPHOIST_INLOOP=1`, opt-in)

With `ivsr` the header read `ldr w0, [x4], #20` and two arms paid
`sub x0, x4, #20`: phase 2 of vendored Cranelift's `bump_hoist` rewrites every
other use of the base as `q - k` so the post-index fires, assuming those uses
leave the loop. `INLOOP` skips a base read again in a block every trip runs.
Alone it loses: pulldown-cmark +0.22% (+109k executed jumps: the bump kept in
the latch keeps that block), compression +0.13%.

## SLOTCOMB

Cap at two terms (a third piece costs a shift and an OR against one store:
regex +0.06% before). Single-read slots only (blake3 +3k loads before).
Committed `92b450c6`; no program worse, ready to flip after gate and crates.

## Afternoon: decide after allocation (`PLIRON_IVSR=2`)

No CLIF-level rule separated the winners from the losers, so the backend
now decides per function after register allocation: apply `ivsr` to a copy
of the optimized function, compile both, and keep the copy when its
frequency-weighted code is smaller. The cost is a new hook in vendored
Cranelift's emitter: each block's bytes / 4 times its placement frequency,
regalloc's moves, spills and reloads included (`pliron_cost_take`). Two
scratch compiles happen only where `ivsr` changes something.

Static frequencies do not know trip counts. lol_html's attribute map-fold
(one to three trips) looked 2.7% cheaper with the rewrite and lost (+14k
executed: a callee save and the entry multiply per call), while brotli's
loop looked 0.5% cheaper and won 1.2%. The cost is therefore split: the
copy must also not grow the code that runs at most once per call (blocks
with frequency at most the entry's). That rejects the map-fold and keeps
brotli's `BrotliCreateHqZopfliBackwardReferences` and `UpdateNodes`.

`INLOOP` became a count. pulldown-cmark's byte cursor is read once more, by
its end test, and its latch is `add; b`: fusing costs one `sub` and empties
the latch, so the old "skip if read every trip" rule paid a jump per byte
(+109k). Now a base is skipped only when it has more every-trip use blocks
than an emptied latch saves.

## Evening: html's lowercase loop (`PLIRON_VEC_REM`, `PLIRON_VEC_MASKSHL`, opt-in)

html's per-function table showed `BytesCow::as_lowercase_string` at
1.83M against LLVM's 30.7k, but LLVM keeps the inner
`Bytes::as_lowercase_string` (1.40M) out of line: the real difference is
+0.40M. The per-line table's top entry, `core/src/num/mod.rs:715`
(`u8::to_ascii_lowercase`, 750k against 13.8k), is line attribution too:
LLVM's vector code is charged to other lines.

`make_ascii_lowercase` per call by length (instructions, ours / LLVM):
8 bytes 90 / 34, 16: 162 / 42, 40: 379 / 66, 63: 585 / 142, 1000: 825 /
404. We vectorized only in 64-byte steps. `VEC_REM` converts the kept
scalar loop again (half width on aarch64): 8: 46, 16: 55, 40: 86, 63: 170,
1000: 487 with `MASKSHL`. A first version at full width with search loops
included cost html +0.28% (`TagScanner::data_state` +182k, a search
loop's short trips). This one costs html +0.063%, all of it in
`as_lowercase_string` (+45.8k, the same as the full-width version): the
names lol_html lowercases are mostly under 8 bytes, and the second
dispatch (`subs; csel` recount, `add`, `cmp`, `b.lo`) runs on every call.
Not a lever for html; both knobs stay opt-in.

## Night: html's `tag_is_one_of!` chains (`PLIRON_BRTHREAD`)

The per-line table's `html/tag.rs:104` (`tag_is_one_of!`, 621k against
151k) is `name == Tag::A || name == Tag::B || ..` over
`LocalName::Hash(u64) | Bytes(..)`. Each `==` tests the variant, then the
payload. After `loadfwd` the variant loads are one value, but every link
still re-tests it in a block of its own (`brif v4`, reached from the
not-Hash path and from a failed compare inside the Hash path): 21 `cbz`
plus a payload reload per compare for `is_void_element`. `jumpthread`
reads only edge arguments; `fold_dominated_conds`/`celim` fold a branch
its own dominator decides, not a join whose every edge decides it.
`brthread` retargets those edges (facts from single-edge `brif`s,
inherited down the dominator tree; chains followed). Microbench with
lol_html's constants: 308.9M -> 207.2M instructions, LLVM 214.7M (it
compares eight constants at a time in vector registers).

## Late night: multi-latch rotation (`PLIRON_LOOPROT_MULTI`, opt-in)

`LocalNameHash::update` keeps one top exit test and every `match` arm ends
`mov; b top`. `looprot` now copies the test into up to `k` latches. The
microbench goes 164.8M -> 146.1M (LLVM 147.0M).

| `k=4`, rule | blind-sig | pulldown | regex | compression | html | json | protobuf |
|---|---|---|---|---|---|---|---|
| none | -0.032% | -0.082% | +0.301% | +0.493% | -0.578% | -0.059% | -0.015% |
| header values stay in header | +0.129% | +0.048% | +0.092% | **-0.399%** | **-0.426%** | -0.058% | -0.016% |

Compression's first loss was `is_mostly_utf8` (+240k): its header also adds
to `size_utf8`, so every latch recomputed it. regex's remaining loss is
aho-corasick's `leftmost_find_at_no_state` (+49k executed loads): after the
copy the loop-invariant end bound has a use in each latch and regalloc
reloads it (`ldr x3, [sp, #64]`) in the hot latch; the same value is a
call's fourth argument elsewhere in the function. A call-free-body rule did
not catch it (the rotated header is not the loop with the call). Opt-in
until regalloc keeps such a bound in a register, or a cost check after
allocation decides (the `ivsr::pick` approach, but `looprot` runs mid-
pipeline).

## Split budget (`PLIRON_RA2_MAXSPLITS`)

The regex loss under `LOOPROT_MULTI` came from regalloc2. aho-corasick's end
bound arrives in `x3`, a call at the entry clobbers `x3`, and the value had
already used upstream's two splits on its loops: the third request fell back
to minimal bundles. The hot latch's reload then hinged on which register a
temporary took. With a budget of 4 the loop keeps the bound and the
automaton pointer in registers, with or without the rotation.

## Partial inlining of entry guards (`PLIRON_PARTINLINE`)

html's state functions exist on both sides, so they compare cleanly:
`finish_tag_name` 1.39M (LLVM) vs 2.36M, `tag_name_state` 1.09M vs 1.73M,
`tag_open_state` 0.54M vs 0.96M, `data_state` 1.03M vs 1.41M (callgrind
per-address counts against the disassembly). `finish_tag_name` runs 66
instructions per call for LLVM, 112 for us. The largest single difference:
every call (21,082) calls `drop_glue::<TreeBuilderFeedback>`, which the
inliner refused (cost 151 > 64: the `Box<dyn FnMut>` variant's drop is
inlined into it), for a variant that owns nothing. The call also stops the
`Option` result just stored on the stack from forwarding to the test after
it. LLVM inlines and folds it.

The new IR pass copies such a callee's entry guard in front of each call.
Three things kept it from firing at first: it ran after `xcgu-home` (the
drop glue is a cross-CGU copy that becomes an import there), calls carry
an unused result even when void, and cargo hides rustc's plain stderr
(trace by running the crate's `rustc` command from `cargo build -vv`).
Without a branch expectation layout put the skip out of line (+32k
jumps); with it:

| | blake3 | blind-sig | pulldown | regex | compression | html | json | protobuf |
|---|---|---|---|---|---|---|---|---|
| `PARTINLINE` | 0 | -0.031% | noise | **-0.102%** | 0 | **-0.045%** | 0 | noise |

Left: in `finish_tag_name` the guard sits at a join whose two predecessors
each know the tag is not 2 (a match chain, and a `None` result), but the
reload of the tag is not forwarded through the join and `brthread` only
reads branch conditions on one value. Folding it is worth about 66k more
on html.
